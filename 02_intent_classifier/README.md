# Demo 2：客服意图分类 —— 逻辑回归 vs 轻量 MLP

## 它解决什么问题

客服 Agent 接到一条用户消息，第一步要判断意图：是退款、退货、物流查询，
还是故障报修？判断错了，后面接的流程全错。
这个 demo 用三种做法做同一个 8 分类任务，把差距和原因都摆出来。

## 三个模型

| 模型 | 说明 | 需要训练 |
| --- | --- | --- |
| `KeywordBaseline` | 每类取一批高区分度词，按命中词的 IDF 之和打分 | 否，纯统计 |
| `SoftmaxRegression` | 多项逻辑回归 + L2，手写 mini-batch Adam | 是 |
| `MLP` | 一层隐藏层（16 维）ReLU + softmax，同特征同优化器 | 是 |

三者用**完全相同的 TF-IDF 特征**（词级 + 字符二元组，约 1600 维），
所以差距只来自模型本身，不来自特征工程。

## 数据

- 训练集：8 类 × 14 条手写样本，再用同义替换（退款→退钱）和口语前缀/后缀
  （"你好，""急等"）扩增到 430 条；
- 留出集：8 类 × 2 条 = **16 条手写样本，不参与训练也不参与扩增**。

扩增出来的样本绝不能进测试集，否则准确率会假高。这一点在代码里是硬约束，
`smoke_test.py` 里有一条断言专门检查训练集与测试集不重叠。

## 怎么跑

```bash
python classifier.py       # 训练 + 打印指标 + 4 折交叉验证
python ../serving.py       # 起网页界面，输入任意一句话看三个模型同时预测
```

开发期脚本：`python bench.py`（分阶段计时）、`python tune.py`（超参小网格）。

## 实测（留出集 16 条）

| 模型 | accuracy | 95% 置信区间 | macro-F1 |
| --- | --- | --- | --- |
| 关键词打分（baseline） | 0.813 | — | — |
| 逻辑回归 + TF-IDF | **0.938** | 0.718 ~ 0.988 | 0.938 |
| 轻量 MLP（1 隐层） | **0.938** | 0.718 ~ 0.988 | 0.938 |

4 折交叉验证（未扩增的 112 条手写数据）：逻辑回归 0.672 ± 0.064，MLP 0.589 ± 0.053。
**折间波动比模型差距还大**，所以留出集上的 0.938 要谨慎解读——
这也是接口里返回 Wilson 置信区间的原因。

## 三条结论

1. 有训练的模型明显强于关键词规则（0.94 vs 0.81）；
2. 加非线性（MLP）没有带来收益，**瓶颈是样本量不是模型容量**，
   直接换 BERT 的边际收益有限，更该做的是补真实工单数据；
3. 置信度比准确率更值得工程化：`/api/classify` 会按置信度和与第二名的差值，
   输出"自动答复 / 坐席确认 / 转人工"的建议，低置信度直接兜底到人工。

## 关于"轻量 BERT"

本 demo 刻意不装 `transformers`/`torch`（保证零依赖可跑），
所以用 MLP 作为轻量模型的代理；`classifier.py` 里保留了 `transformer_available()`
探针，装了依赖后把 MLP 换成 `AutoModelForSequenceClassification` 微调即可，
评测与接口代码不需要改。

## 性能备注

第一版把 TF-IDF 转成稠密 `list[float]` 再喂 MLP，一个 epoch 要几十秒
（2000×64 的全矩阵乘法在纯 Python 里非常慢）。
改成稀疏 `dict{下标: 权重}` + 稀疏梯度累积后，同样的训练几秒跑完，指标完全一致。
这个改动在 `classifier.py` 顶部的 `nonzeros()` / `dot_dense_sparse()` 里。
